# 10. 문제 해결

## 10.1 진단 순서

1. **실행 기록**에서 실패한 실행을 연다
2. 빨간 X 표시된 액션을 펼친다
3. **입력**을 먼저 본다 — 기대한 값이 들어갔는가?
4. **출력 / 오류 메시지**를 본다
5. 원시 출력 표시로 실제 JSON 구조를 확인한다

> 대부분의 원인은 "출력이 이상하다"가 아니라 **"입력이 이미 이상했다"** 입니다.
> 오류가 난 액션의 앞 단계부터 거슬러 올라가세요.

## 10.2 자주 나오는 오류

### `BadRequest` / `InvalidTemplate` — 표현식 오류

```
The template language expression '...' cannot be evaluated because
property 'xxx' doesn't exist
```

- 원인: 없는 속성에 접근. 안전 접근자 누락.
- 해결: `?['속성']` 로 바꾸고, 필요하면 `coalesce()`로 기본값 지정.
- 확인: 앞 단계의 **원시 출력**에서 실제 키 이름·대소문자를 확인하세요.

```
The template language function 'int' was invoked with a parameter that is not valid
```

- 원인: 빈 문자열이나 `null`을 `int()`에 넣음.
- 해결: `@int(coalesce(값, 0))` 또는 조건으로 먼저 걸러내기.

### 액션을 못 찾는 오류

```
The action 'HTTP 요청' referenced by ... is not defined
```

- 원인: 표현식에서 **공백을 `_`로 안 바꿨거나**, 액션 이름을 바꿨는데 표현식이 남아 있음.
- 해결: `body('HTTP_요청')` 형태로 수정. 이름 변경 시 참조하는 표현식을 전부 찾아 고치세요.

### `Unauthorized` (401) / `Forbidden` (403)

- 연결이 만료됨 → 플로우 상세 화면의 **연결** 섹션에서 다시 인증
- 계정이 대상 리소스에 권한이 없음 → SharePoint 사이트/목록 권한 확인
- 배포 후라면 **연결 참조가 잘못된 계정**을 가리킬 수 있습니다(8장)
- HTTP 액션이면 토큰 만료 또는 헤더 오타

### `429 Too Many Requests`

- 커넥터 스로틀링. 7.3절 참고.
- 반복 동시성 낮추기 → 지연 넣기 → 지수 재시도 → 호출 횟수 자체 줄이기

### `Payload/Request too large`

- 큰 파일이나 배열을 한 번에 다루고 있음
- 파일은 청크 전송 지원 여부 확인, 배열은 `take`/`skip`으로 나눠 처리

### 시간 초과 (Timeout)

- 동기 HTTP 응답은 약 120초 제한. 오래 걸리면 202를 먼저 반환하고 비동기 처리(9.4절).
- 액션 시간 제한(`PT2M` 등)에 걸렸는지 확인.

### "제한 또는 할당량을 초과했습니다" (SharePoint)

- 목록 보기 임계값(5,000). 필터/정렬 열을 **인덱싱**하세요(7.4절).

### JSON 구문 분석 실패

```
Invalid type. Expected String but got Null
```

- 원인: 자동 생성 스키마가 `null`을 허용하지 않음.
- 해결: 해당 속성을 `"type": ["string", "null"]` 로 수정하고, `required` 배열에서 제거.

### 트리거가 아예 안 걸림

체크 순서:

1. 플로우가 **켜져 있는가?** (특히 배포 직후)
2. **트리거 조건**에 오타가 있는가? → 조건을 잠시 지우고 테스트
3. 트리거 대상(사이트/목록/폴더)이 맞는가? 배포 후 개발 대상을 가리키고 있지 않은가?
4. 연결이 만료되었는가?
5. 폴링 트리거라면 아직 주기가 안 됐는가?
6. 소유자 계정이 비활성화되었는가?

> 트리거 조건은 **문법이 틀려도 저장됩니다.** 그리고 아무 이벤트도 안 잡힙니다.
> 트리거가 안 걸리면 가장 먼저 의심할 곳입니다.

### 무한 루프

증상: "항목이 수정되는 경우" 트리거 플로우가 자기가 만든 수정으로 다시 실행됨.

해결:

- 트리거 조건에서 **플로우가 쓰는 계정의 수정은 제외**
  `@not(equals(triggerOutputs()?['body/Editor/Email'], 'flow-svc@contoso.com'))`
- 또는 "처리됨" 플래그 열을 두고 `@equals(triggerOutputs()?['body/처리됨'], false)`

> Power Automate에는 루프 감지 기능이 있어 일정 횟수 이상 반복되면 플로우를 **자동으로 끕니다.**
> 갑자기 플로우가 꺼져 있다면 이걸 의심하세요.

### 배포 후에만 실패

- 환경 변수가 기본값(개발 값)으로 들어갔는지 확인
- 연결 참조가 대상 환경 계정에 연결되었는지 확인
- HTTP 트리거 URL이 바뀌었으므로 **호출하는 쪽 설정**도 갱신했는지 확인
- 운영 환경의 목록/테이블 구조가 개발과 동일한지 확인

## 10.3 디버깅 도구

| 방법 | 용도 |
| --- | --- |
| `작성` 액션으로 중간값 찍기 | 표현식 단계별 확인 |
| 원시 출력 표시 | 실제 JSON 키 이름·구조 확인 |
| `@{string(outputs('X'))}` | 객체 전체를 문자열로 확인 |
| 테스트 → 수동으로 / 이전 실행 데이터 사용 | 같은 입력으로 반복 테스트 |
| 코드 보기(Peek code) | 액션의 실제 정의(JSON) 확인 |
| 플로우 체커 | 저장 시 경고·오류 목록 |

**"이전 실행 데이터 사용"** 이 특히 유용합니다.
실패한 실행과 똑같은 입력으로 다시 돌려 볼 수 있어, 이벤트를 다시 만들 필요가 없습니다.

## 10.4 자주 묻는 질문

**Q. 플로우를 다른 사람에게 넘기려면?**
공동 소유자로 추가하면 됩니다. 다만 **연결은 함께 넘어가지 않습니다.**
받는 사람이 자기 연결로 다시 지정해야 합니다. 근본 해결은 서비스 계정 + 연결 참조입니다(8장).

**Q. 실행 기록을 28일 넘게 보관하려면?**
직접 적재해야 합니다(9.9절). 또는 Dataverse 감사 기능이나 관리 커넥터 활용.

**Q. 플로우를 복사하려면?**
플로우 목록에서 **다른 이름으로 저장**. 단, 솔루션 안팎을 오가는 복사는 제약이 있습니다.

**Q. 실수로 지운 플로우를 복구하려면?**
Power Platform 관리 센터에서 일정 기간 내 복구가 가능한 경우가 있지만 보장되지 않습니다.
**솔루션을 내보내 zip을 보관**하는 습관이 유일한 확실한 백업입니다.

**Q. 표현식이 너무 길어져서 관리가 안 됩니다.**
`작성` 액션으로 쪼개세요. 성능 손해는 거의 없고 디버깅은 훨씬 쉬워집니다.

**Q. 반복이 너무 느립니다.**
7.2절을 순서대로 적용하세요. 대부분 `선택`/`배열 필터링`으로 해결됩니다.

**Q. Excel 파일을 다루는 좋은 방법은?**
Excel Online(비즈니스) 커넥터는 **표(Table)로 서식 지정된 범위**만 다룹니다.
표가 아니면 인식하지 못합니다. 복잡한 Excel 조작은 Office 스크립트나 VBA(11장) 쪽이 낫습니다.

**Q. 플로우가 갑자기 꺼졌습니다.**
가능한 원인: 무한 루프 감지, 연속 실패로 인한 자동 비활성화, 소유자 계정 비활성화,
라이선스 만료, 장기간 트리거 이벤트 없음(일부 트리거). 실행 기록과 소유자 알림 메일을 확인하세요.
