# 1. Power Automate 기초

## 1.1 Power Automate란

Microsoft Power Platform에 속한 워크플로 자동화 서비스입니다.
"어떤 일이 생기면(트리거) → 이런 작업을 한다(액션)" 형태로 업무를 자동화합니다.

내부 엔진은 Azure Logic Apps와 동일한 **워크플로 정의 언어(WDL, Workflow Definition Language)** 를 씁니다.
그래서 표현식 함수 레퍼런스는 Logic Apps 문서를 봐야 합니다(4장 참고).

## 1.2 플로우의 종류

| 종류 | 실행 위치 | 사용 사례 |
| --- | --- | --- |
| **클라우드 플로우** | Microsoft 클라우드 | API가 있는 서비스 간 연동 (SharePoint, Outlook, Teams, SQL 등) |
| **데스크톱 플로우** | 사용자 PC / VM | API가 없는 레거시 프로그램 조작 (RPA) |
| **비즈니스 프로세스 플로우** | Dataverse | 모델 기반 앱의 단계별 진행 가이드 |

클라우드 플로우는 다시 **트리거 방식**에 따라 세 가지로 나뉩니다.

| 유형 | 시작 방법 | 예시 |
| --- | --- | --- |
| 자동화된 클라우드 플로우 | 이벤트 발생 시 | 메일 수신, 목록 항목 생성, 파일 업로드 |
| 인스턴트 클라우드 플로우 | 사람이 직접 실행 | 버튼 클릭, Teams 메시지에서 실행, **HTTP 요청 수신** |
| 예약된 클라우드 플로우 | 일정에 따라 | 매일 09:00, 매주 월요일 |

> **선택 기준**: 대상 시스템에 API나 커넥터가 있으면 무조건 클라우드 플로우입니다.
> 데스크톱 플로우(RPA)는 화면 좌표·UI 요소에 의존해서 깨지기 쉽고 라이선스 비용도 높습니다.
> "API가 없을 때만" 쓰는 마지막 수단으로 보세요.

## 1.3 구성 요소

```
[트리거]  하나. 플로우를 시작시킨다.
   ↓
[액션 1]  ← 커넥터를 통해 외부 서비스 호출
   ↓
[액션 2]  ← 이전 단계의 출력을 동적 콘텐츠 / 표현식으로 참조
   ↓
[액션 3]
```

- **커넥터(Connector)**: 서비스와 통신하는 어댑터. 표준/프리미엄/사용자 지정으로 나뉩니다.
- **연결(Connection)**: 커넥터를 쓰기 위한 인증 정보. 만든 사람 계정에 묶입니다.
  → 담당자가 퇴사하면 플로우가 멈추는 사고가 여기서 납니다. 8장 "연결 참조" 참고.
- **동적 콘텐츠(Dynamic content)**: 이전 단계의 출력을 UI에서 고르는 기능.
- **표현식(Expression)**: 동적 콘텐츠로 안 되는 계산·변환을 처리하는 함수식(4장).

## 1.4 라이선스 개요

| 라이선스 | 범위 | 핵심 차이 |
| --- | --- | --- |
| Microsoft 365 포함(시드) | 사용자당 | **표준 커넥터만.** SharePoint, Outlook, Teams, OneDrive 등 |
| Power Automate Premium | 사용자당 | 프리미엄·사용자 지정·온프레미스 커넥터, 참석형 RPA, Dataverse 용량 |
| Power Automate Process | 플로우/프로세스 단위 | 사용자 수와 무관. 무인 실행되는 공용 플로우에 적합 |
| Power Automate Hosted Process | 프로세스 단위 | Microsoft가 호스팅하는 무인 RPA 머신 포함 |

**꼭 알아둘 점**

- **HTTP 액션·HTTP 트리거·SQL Server·Dataverse·사용자 지정 커넥터는 프리미엄입니다.**
  VBA 연동(11장)은 HTTP 트리거를 쓰므로 프리미엄 라이선스가 필요합니다.
- 하루 API 요청 한도가 라이선스별로 다릅니다. 반복이 많은 플로우는 한도에 먼저 걸립니다(7장).
- 제품 이름과 가격 체계는 자주 바뀝니다. 공식 가격 페이지에서 확인하세요.

## 1.5 환경(Environment)

환경은 플로우·앱·데이터가 담기는 **격리된 컨테이너**입니다.

| 환경 유형 | 용도 | 주의 |
| --- | --- | --- |
| 기본(Default) | 개인 실험용 | **모든 사용자가 접근 가능.** 운영 업무용으로 쓰면 안 됨 |
| 프로덕션 | 실제 운영 | 개발/테스트/운영으로 분리 권장 |
| 샌드박스 | 테스트 | 운영 환경 복사·초기화 가능 |
| 개발자 | 1인 개발 | 무료, 개인 학습용 |

> **가장 흔한 실수**: 기본 환경에 솔루션 없이 플로우를 만들고, 나중에 운영 환경으로 옮기려다 막히는 것.
> 처음부터 **전용 환경 + 솔루션 안**에서 만드세요(8장).

## 1.6 첫 플로우 만들기

목표: *SharePoint 목록에 항목이 추가되면 Teams로 알림을 보낸다.*

1. <https://make.powerautomate.com> 접속 → 왼쪽 **환경**이 올바른지 확인
2. **솔루션** → **새 솔루션** → 이름·게시자 지정 (기본 환경이 아니라면 반드시 솔루션 안에서 작업)
3. 솔루션 안에서 **새로 만들기 → 자동화 → 클라우드 플로우 → 자동화된**
4. 트리거: `SharePoint - 항목이 만들어지는 경우` 선택 → 사이트 주소·목록 이름 지정
5. **새 단계** → `Microsoft Teams - 채팅 또는 채널에 메시지 게시`
6. 메시지 본문에 동적 콘텐츠로 `제목`, `작성자 표시 이름` 삽입
7. **저장** → **테스트 → 수동으로** → 목록에 항목을 하나 추가해 확인

### 실행 기록 보는 법

플로우 상세 화면의 **28일 실행 기록**에서 각 실행을 클릭하면 단계별 입력/출력을 볼 수 있습니다.
디버깅의 90%는 여기서 끝납니다. 실패한 단계를 펼쳐 **입력이 기대한 값인지** 먼저 확인하세요.

> 실행 기록은 28일만 보관됩니다. 장기 감사 로그가 필요하면 별도로 적재해야 합니다(9장 레시피 참고).

## 1.7 만들기 전에 정할 것

체크리스트로 두면 나중에 다시 만드는 일이 줄어듭니다.

- [ ] 이 자동화의 **소유자**는 누구인가? (개인 계정 대신 서비스 계정 / 공동 소유자 지정)
- [ ] 실패하면 **누가 어떻게 알게 되는가?** (6장)
- [ ] 처리량은 어느 정도인가? 하루 몇 건? (7장의 요청 한도와 대조)
- [ ] 개발 → 운영으로 어떻게 옮길 것인가? (8장)
- [ ] 재실행해도 안전한가? (같은 항목을 두 번 처리해도 문제없는 **멱등성**)
