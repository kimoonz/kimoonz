# 확률(베이지안) 기반 해외선물 매매 타이밍 알림

**금(GC) · 은(SI) · 크루드오일(CL) · 나스닥100(NQ)** 네 종목에 대해
베이지안 방식으로 "지금 오를 확률"을 계산하고, 확률이 임계치를 넘으면
**텔레그램으로 매수/매도 신호를 보내는** 프로그램입니다.

자동 주문은 하지 않습니다. 알림만 받고 주문은 직접 넣습니다.

---

## ⚠️ 먼저 읽으세요 — 실제 검증 결과

**이 모델은 현재 피처 구성으로는 방향 예측 엣지를 찾지 못했습니다.**
2008~2026년 일봉 전 구간을 워크포워드 검증(각 시점에서 그때까지의 데이터로만
재학습, 미래 정보 차단)한 결과입니다.

| 종목 | 표본 | 기준확률 | AUC | Brier (기준선) | 보정계수 a | 신호 | 적중률 | 누적 |
|---|---|---|---|---|---|---|---|---|
| 금 | 4,646 | 53.3% | 0.492 | 0.2507 (0.2489) | 0.043 | 87건 | 55.2% | +7.5R |
| 은 | 4,647 | 52.7% | 0.480 | 0.2515 (0.2492) | 0.049 | 250건 | 47.6% | −16.6R |
| 크루드오일 | 4,647 | 51.5% | 0.480 | 0.2506 (0.2498) | 0.026 | **0건** | — | 0 |
| 나스닥100 | 4,650 | 54.7% | 0.479 | 0.2491 (0.2478) | 0.028 | **0건** | — | 0 |

읽는 법:

- **AUC 0.5 = 동전 던지기.** 네 종목 모두 0.48 근처입니다. 게다가 라벨이
  10봉씩 겹치므로 실질 표본 수는 표시된 수의 약 1/10이고, 그 기준에서
  0.48은 0.5와 통계적으로 구분되지 않습니다.
- **Brier가 기준선보다 나쁩니다.** 모든 종목에서 "그냥 기준확률을 그대로
  말하기"보다 예측이 살짝 못합니다.
- **보정계수 a ≈ 0.03~0.05** 는 모델이 스스로 내린 판정입니다.
  "내 증거들은 확률을 거의 움직일 자격이 없다"는 뜻으로, 사후확률을
  기준확률(그 종목의 장기 상승 비율) 근처로 눌러버립니다.
- **금의 +7.5R도 유의하지 않습니다.** 87건에서 적중률 55.2%인데 기준확률이
  53.3%입니다. 표본 87건의 적중률 표준오차가 약 5.3%p라 이 차이는 잡음입니다.
- **이건 파이프라인이 정상이라는 신호이기도 합니다.** 미래 정보가 샜다면
  AUC가 0.7 이상으로 나옵니다. 0.5 근처는 "누수 없이 정직하게 어렵다"는 뜻입니다.

**그래서 기본 설정에서 이 프로그램은 대부분 "관망"이라고 말합니다.
그게 올바른 동작입니다.** 억지로 신호를 만들어내지 않습니다.

### 드리프트를 신호로 착각하지 않기

개발 중에 비대칭 배리어(목표 2ATR / 손절 1ATR)에서 평균 **+0.8R**이라는
결과가 나온 적이 있습니다. 두 가지 함정이었습니다.

1. **매도의 손익비를 뒤집지 않았습니다.** 매도 포지션은 하단이 목표(1ATR),
   상단이 손절(2ATR)이라 손익비가 1:0.5로 역전됩니다. 이걸 매수와 같은 2:1로
   계산하고 있었습니다. 고치니 +0.8R이 **−0.1R**로 뒤집혔습니다.
2. **절대 임계치가 드리프트에 먹혔습니다.** 비대칭 배리어에서는 기준확률이
   0.40으로 내려가는데 매도 임계치가 0.42라, **모든 봉이 자동으로 매도 신호**가
   됐습니다(금 2,949건 전부 매도, 누적 −429R). 상승 자산을 불리한 손익비로
   계속 공매도한 셈입니다.

그래서 이제 신호는 **기준확률 대비 초과분**을 요구합니다(`min_prob_over_base`).
증거가 만들어낸 부분만 신호로 인정한다는 뜻이고, 이 필터를 넣은 뒤
크루드오일과 나스닥의 드리프트성 신호 수백 건이 **0건**으로 정리됐습니다.
알림 메시지에도 "기준 54.9% 대비 +8.5%p"처럼 항상 같이 표시됩니다.

### 임계치를 낮추면?

`python run.py backtest --tune` 이 보여주는 금의 예입니다.

```
임계치  신호수  월평균   적중률    평균R   누적R
52%    232    1.0   0.483  -0.056  -13.0
54%    190    0.9   0.453  -0.116  -22.0
56%    132    0.6   0.447  -0.125  -16.5
58%     87    0.4   0.552  +0.086   +7.5
60%     26    0.1   0.577  +0.134   +3.5
```

임계치를 낮추면 알림은 많아지지만 성과는 나빠집니다. 직접 확인하고 고르세요.

### 그럼에도 쓸모 있는 이유

1. **확률이 정직합니다.** "63%"라고 말하면 실제로 그 근처에서 맞습니다
   (신뢰도 곡선으로 검증). 근거 없는 확신을 주지 않습니다.
2. **손절·목표·계약 수가 자동 계산됩니다.** 계좌 대비 리스크를 지키는
   포지션 크기를 알려주고, 계좌가 부족하면 얼마가 필요한지 알려줍니다.
3. **새 아이디어를 검증하는 틀이 갖춰져 있습니다.** 피처를 추가하고
   `backtest` 를 돌리면 그게 진짜 도움이 되는지 바로 나옵니다.
   위 두 함정 같은 실수를 잡아주는 게 이 틀의 핵심 가치입니다.

## 어떻게 동작하나

### 1. 무엇을 예측하는가 — 삼중 배리어

"내일 오를까?"는 답하기 애매합니다. 대신 이렇게 정의합니다.

```
지금 종가에서 출발해서
  상단 = 종가 + 1.0 × ATR   (목표)
  하단 = 종가 − 1.0 × ATR   (손절)
앞으로 10봉 안에 어느 쪽을 먼저 건드릴까?
```

`P(상단 먼저)` 가 이 프로그램이 계산하는 확률입니다.
바로 그래서 이 확률이 **실제 주문의 손절·목표와 정확히 대응**합니다.

### 2. 어떻게 계산하는가 — 베이즈 로그오즈

```
사후 로그오즈 = 사전 로그오즈 + Σ (신뢰도ᵢ × 로그우도비ᵢ)
```

- 각 지표(모멘텀, RSI, 이격도, 변동성, 갭, 거래량, 달러지수, VIX 등)를
  학습 구간 분위수로 5구간으로 나눕니다.
- 구간마다 `우도비 = P(이 구간 | 상승) / P(이 구간 | 하락)` 을 추정합니다.
- 표본이 적은 구간은 **경험적 베이즈로 0쪽으로 축소**합니다
  (`신뢰도 = n / (n + 40)`). 근거가 얇으면 확률을 안 움직입니다.
- 증거들의 로그우도비를 **더합니다**. 로그오즈에서 덧셈이라
  각 지표가 판단을 얼마나 밀었는지 그대로 읽을 수 있습니다 —
  알림의 "판단 근거" 항목이 이 값입니다.

### 3. 과신 교정 — 여기가 핵심

나이브 베이즈는 지표들이 서로 독립이라고 가정하는데, 실제로는
모멘텀과 이격도처럼 같은 이야기를 하는 지표가 많습니다. 그대로 더하면
같은 증거를 여러 번 세어 확률이 과장됩니다.

그래서 **퍼지드 K-폴드 교차검증**으로 보정 계수를 학습합니다.

```
p = sigmoid(a × 점수 + b)
```

- 학습 구간을 5개로 나눠 각 조각을 나머지로 예측 → 폴드 밖 점수를 모읍니다.
- 라벨이 미래 10봉을 보므로 폴드 경계 앞뒤 10봉을 학습에서 제외합니다(embargo).
  이걸 빼먹으면 보정계수가 낙관적으로 부풀려집니다.
- `a < 1` 이 정상이고, **a가 확률을 믿을 수 있게 만드는 장치**입니다.

### 4. 국면 필터 — HMM

가우시안 은닉 마르코프 모델(Baum-Welch, numpy 직접 구현)로 수익률을
3개 국면(하락/횡보/상승)으로 나눕니다. 추론은 **전향 필터링만** 쓰므로
미래 정보가 새지 않습니다. 국면 사후확률은 소프트 증거로 로그오즈에 더해집니다.

### 5. 진입 판정 — 세 관문을 모두 통과해야

확률이 임계치를 넘는 것만으로는 부족합니다.

1. **절대 임계치** — `P(상승) ≥ 0.58` (매수) 또는 `≤ 0.42` (매도)
2. **기준확률 대비 초과분** — `P(상승) − 기준확률 ≥ 0.02`
   그 종목이 원래 오르는 자산이라서 확률이 높은 것과, 증거가 실제로
   말해주는 것을 구분합니다.
3. **비용 차감 기대값** — `승률 × 손익비 − (1 − 승률) − 비용 ≥ min_edge_r`

매도 포지션은 배리어 역할이 뒤바뀌므로(하단이 목표, 상단이 손절)
손익비를 역수로 계산합니다.

## 시작하려면 이 5가지가 필요합니다

| # | 필요한 것 | 어디서 | 없으면 |
|---|---|---|---|
| 1 | **텔레그램 봇 토큰** | @BotFather → `/newbot` | 알림 발송 불가 |
| 2 | **텔레그램 chat_id** | `python scripts/setup_telegram.py` | 알림 발송 불가 |
| 3 | **계좌 평가금 (USD)** | `config.yaml` → `account.equity_usd` | 계약 수를 못 정함 |
| 4 | **증권사 왕복 수수료 · 슬리피지** | `config.yaml` → `costs` | 기대값이 낙관적으로 나옴 |
| 5 | **브리핑 받을 시각** | `config.yaml` → `alerts.briefing_time_kst` | 기본 08:00 KST |

3~5번은 기본값으로도 돌아가지만, **3번(계좌 평가금)이 틀리면 계약 수가
전부 틀립니다.** 4번은 기대값 계산에 직접 들어가서, 실제보다 낮게 잡으면
손해나는 신호를 통과시킵니다.

선택적으로 알려주면 더 맞춰줄 수 있는 것:

- **하루 몇 번까지 알림을 받고 싶은지** → `long_threshold` / `short_threshold` 조정
- **최대 보유 기간** → `label.horizon` (기본 일봉 10봉, 1시간봉 8봉)
- **손절 폭 선호** → `label.up_mult` / `down_mult` (ATR 배수)
- **이미 보유 중인 포지션** → 현재는 반영하지 않습니다. 신규 진입 신호만 보냅니다.

## 텔레그램 연결 (5분)

1. 텔레그램에서 **@BotFather** 를 찾아 대화를 엽니다.
2. `/newbot` → 봇 이름과 사용자명을 정하면 **토큰**을 줍니다.
   (`123456789:AAE...` 형태)
3. 방금 만든 봇을 검색해서 대화창을 열고 **`/start` 를 한 번 보냅니다.**
   (이걸 안 하면 봇이 나에게 메시지를 못 보냅니다)
4. 아래를 실행하면 `.env` 파일까지 자동으로 만들어 줍니다.

```bash
python scripts/setup_telegram.py
```

5. 연결 확인:

```bash
python run.py telegram-test
```

수동으로 하려면 `.env` 파일을 만들고:

```
TELEGRAM_BOT_TOKEN=여기에_토큰
TELEGRAM_CHAT_ID=여기에_숫자_ID
```

`.env` 는 `.gitignore` 에 있어서 깃에 올라가지 않습니다.

## 사용법

```bash
# 지금 상태만 확인 (발송 안 함)
python run.py once --dry-run

# 지금 평가하고 신호가 있으면 텔레그램 발송
python run.py once

# 전체 브리핑 강제 발송
python run.py once --briefing

# ★ 상시 감시 — PC에 띄워두는 모드
python run.py watch

# 검증
python run.py backtest --reliability --tune
python run.py backtest -i gold silver -t daily --max-points 2000
```

`watch` 가 하는 일:

- 5분마다(설정 가능) 새로 **마감된** 봉이 있는지 확인합니다.
  진행 중인 봉으로는 신호를 내지 않습니다.
- 새 봉이 마감되면 그 종목만 다시 학습하고 확률을 계산합니다.
- 임계치를 넘고 기대값이 나오면 즉시 알림을 보냅니다.
- 매일 정해진 시각(기본 08:00 KST)에 4종목 브리핑을 보냅니다.
- 장 마감 시간(주말, 매일 17:00~18:00 ET 정비)에는 조용히 대기합니다.
- 어느 종목에서 오류가 나도 나머지는 계속 돕니다. 오류 알림은 1시간에 한 번까지만.

## 부팅 시 자동 시작

PC가 하루에 몇 번 재시작돼도 알림이 끊기지 않게 하는 설정입니다.
발송 이력은 `state/alerts.json` 에 남으므로 **재시작해도 같은 신호를 두 번 보내지 않습니다.**

### Windows

1. `Win + R` → `shell:startup` → 열린 폴더에 `scripts\start_windows.bat`
   바로가기를 넣습니다. (로그인할 때마다 자동 실행)

2. 더 확실하게 하려면 **작업 스케줄러**:
   - `작업 스케줄러` 실행 → `기본 작업 만들기`
   - 트리거: **컴퓨터 시작 시**
   - 동작: 프로그램 시작 → `C:\경로\kimoonz\scripts\start_windows.bat`
   - 속성에서 **"사용자가 로그온했는지 여부에 관계없이 실행"** 체크
   - 조건 탭에서 "컴퓨터가 AC 전원일 때만 실행" **해제**

`start_windows.bat` 은 파이썬이 죽어도 10초 뒤 자동으로 다시 띄웁니다.

### macOS / Linux

```bash
./scripts/start_unix.sh          # 죽으면 자동 재시작
```

Linux에서 부팅 시 자동 시작 (systemd):

```bash
# 파일 안의 CHANGE_ME 를 본인 사용자명/경로로 바꾼 뒤
sudo cp scripts/bayesfutures.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now bayesfutures
journalctl -u bayesfutures -f     # 로그 보기
```

"판단 근거"의 숫자는 **로그오즈 기여도**입니다. 양수면 상승 쪽으로,
음수면 하락 쪽으로 판단을 민 정도이고, 다 더하면 기준확률에서

숫자로 분해되어 나옵니다.**

## ★ 설정에서 꼭 본인 값으로 바꿔야 하는 것

`config.yaml` 에서:

```yaml
account:
  equity_usd: 10000        # ← 본인 계좌 평가금 (계약 수 계산의 기준)
  risk_per_trade_pct: 1.0  # ← 1회 매매에 걸 최대 손실 (%)

costs:
  commission_per_contract: 2.5   # ← 본인 증권사 왕복 수수료
  slippage_ticks: 1.0            # ← 체감 슬리피지

alerts:
  briefing_time_kst: "08:00"     # ← 브리핑 받고 싶은 시각
```

**계좌가 작으면 0계약이 나옵니다.** 예를 들어 계좌 $10,000에 리스크 1%면
$100인데, 금 ATR이 69달러일 때 마이크로 금(MGC) 1계약의 손절 리스크가
$689라 한도를 넘습니다. 이때는:

- 리스크 비율을 올리거나(권장하지 않음),
- 손절을 좁히거나(라벨 배리어도 같이 바꿔야 확률이 유효합니다),
- 변동성이 작을 때만 진입하거나,
- 계좌를 키울 때까지 기다립니다.

프로그램은 억지로 1계약을 만들지 않고 **경고를 띄웁니다.**

## 임계치 조정하기

```bash
python run.py backtest --tune
```

임계치별로 "신호가 몇 건 나오고, 적중률이 얼마고, 평균 몇 R인지"를
표로 보여줍니다. 알림을 자주 받고 싶은지 좋은 신호만 받고 싶은지
직접 고르라는 표입니다. 정한 값을 `config.yaml` 의
`long_threshold` / `short_threshold` 에 넣으면 됩니다.

## 한계와 주의

- **시세는 야후 파이낸스 무료 데이터**입니다. 선물 시세가 **10~15분 지연**될 수 있고,
  야후가 막히면 stooq(일봉만)로 자동 전환합니다. 실시간 호가가 필요하면
  증권사 데이터로 바꿔야 합니다 (`bayesfutures/data.py` 의 `DataLoader` 만 교체).
- **연결 선물(GC=F 등) 데이터**라 만기 롤오버 구간에 가격 점프가 있습니다.
- **거래소 휴일을 반영하지 않습니다.** 다만 휴일엔 새 봉이 안 생겨 알림도 안 나갑니다.
- 라벨이 겹치므로(10봉 horizon) 백테스트의 실질 표본 수는 표시된 수보다 훨씬 적습니다.
  성과 수치를 액면 그대로 믿지 마세요.
- **이건 투자 조언이 아닙니다.** 확률 추정 도구이고, 위 검증 결과가 보여주듯
  현재 엣지는 확인되지 않았습니다. 실계좌 투입 전에 반드시 직접 검증하세요.
