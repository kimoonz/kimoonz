# 확률·추세 기반 해외선물 매매 타이밍 알림

**금(GC) · 은(SI) · 크루드오일(CL) · 나스닥100(NQ)** 네 종목에 대해
**언제 사고 언제 팔지를 텔레그램으로 알려주는** 프로그램입니다.
자동 주문은 하지 않습니다.

두 개의 층으로 되어 있습니다.

| 층 | 하는 일 | 검증 결과 |
|---|---|---|
| **① 추세·분산 배분 전략** | 언제 얼마나 들고 있을지 | ✅ **표본외 샤프 0.99, 최대낙폭 −12.5%** |
| ② 베이지안 단기 확률 | 지금 오를 확률은 얼마인지 | ❌ 엣지 없음 (AUC 0.48) — 참고용 |

**수익을 만드는 건 ①입니다.** ②는 정직하게 "예측이 안 된다"는 결론이
나왔고, 그 결과를 숨기지 않고 그대로 싣습니다.

---

## ✅ 수익이 확인된 구조

2006~2026년 일봉으로 검증했습니다.
**2018년 이전을 개발 구간, 이후를 표본외 검증 구간으로 분리**했고,
왕복 2bp 비용을 뺐습니다.

| 전략 | 샤프 (내/외) | 최대낙폭 (내/외) | 칼마 (외) |
|---|---|---|---|
| 나스닥 단독 보유 | 0.69 / 0.86 | −53.9% / −35.3% | 0.58 |
| 4종목 균등 보유 | 0.48 / 0.92 | −46.6% / −35.4% | 0.54 |
| + 변동성 조절 | 0.58 / 0.96 | −27.6% / −18.8% | 0.54 |
| **+ 추세 이중필터** | **0.82 / 0.99** | **−12.2% / −12.5%** | **0.61** |

**최대낙폭을 −54%에서 −12%로 4분의 1로 줄이면서 샤프는 오릅니다.**
회전율은 연 6회 수준이라 비용도 거의 안 듭니다.

### 왜 되는가

방향을 맞히는 게 아닙니다. 세 가지를 겹칩니다.

**1. 분산** — 네 종목은 서로 다른 데서 움직입니다.

|  | 금 | 은 | 오일 | 나스닥 |
|---|---|---|---|---|
| 금 | 1.00 | 0.79 | 0.16 | **0.03** |
| 은 | 0.79 | 1.00 | 0.21 | 0.14 |
| 오일 | 0.16 | 0.21 | 1.00 | 0.18 |
| 나스닥 | 0.03 | 0.14 | 0.18 | 1.00 |

금과 나스닥의 상관은 0.03입니다. 하나가 무너질 때 다른 하나는 멀쩡합니다.

**2. 변동성 조절** — 각 종목이 목표 변동성만큼만 기여하도록 역변동성으로
비중을 정합니다. 은이 연 45% 흔들리고 나스닥이 26%면, 은을 절반만 담습니다.

**3. 추세 이중필터** — **126일 전과 252일 전 가격을 모두 넘을 때만** 보유합니다.
둘 중 하나라도 아래면 전량 청산. 이게 폭락 구간에서 노출을 끊습니다.

**숏은 넣지 않았습니다.** 검증에서 숏 사이드는 가치를 파괴했습니다
(표본외 평균 샤프 롱숏 0.20~0.36 vs 롱온리 0.54~0.58).

### 파라미터에 맞춘 게 아닙니다

특정 숫자에만 맞은 결과라면 그 값을 벗어나면 무너져야 합니다. 안 무너집니다.

- **추세 창 11개 조합** (42~126일 × 126~378일): 표본외 샤프 **0.72~1.02**, 전부 작동
- **변동성 파라미터 9개 조합** (창 20/60/120 × 목표 10/15/20%): 샤프 **0.94~0.99**
- **비용 민감도**: 0bp에서 샤프 1.01 → 20bp(현실의 10배)에서도 **0.85**

126/252라는 선택이 특별한 게 아니라 **구조 자체가 효과**라는 뜻입니다.

## ⚠️ 계좌 규모가 결정적입니다

선물은 계약 단위로만 거래되고, 마이크로 계약도 명목가치가 큽니다.

| 계약 | 1계약 명목가치 |
|---|---|
| MCL (오일) | $8,298 |
| MGC (금) | $46,165 |
| MNQ (나스닥) | $59,474 |
| SIL (은) | $70,225 |

**은 1계약이 오일 1계약의 8.5배입니다.** 그래서 "각 1계약씩" 같은 단순한
방식은 기형 포트폴리오가 되고, 실제로 검증하면 **최대낙폭 −92%**가 나옵니다.
정수 반올림이 분산 구조를 파괴하기 때문입니다.

계좌별 실측 (목표 변동성 자동 조정, 표본외):

| 계좌 | 담을 수 있는 종목 | 샤프 | 최대낙폭 |
|---|---|---|---|
| $10,000 | 없음 | **거래 불가** | — |
| $25,000 | MCL만 | 0.35 | −12.9% |
| $50,000 | MCL만 | 0.85 | −14.4% |
| $100,000 | MGC, MCL | 0.89 | −8.4% |
| **$200,000** | **4종목 전부** | **0.89** | −4.2% |
| $500,000 | 4종목 전부 | 0.98 | −6.8% |

**먼저 이걸 돌려보세요.**

```bash
python run.py plan --equity 200000
```

계좌 규모로 무엇이 가능한지, 목표 변동성별로 수익·낙폭이 어떻게 달라지는지
표로 보여줍니다. 샤프는 어느 목표 변동성에서도 0.89~0.98로 비슷하므로,
**감당할 수 있는 최대낙폭을 먼저 고르고 그 줄의 값을 쓰면 됩니다.**

## 텔레그램 연결

**이미 `TELEGRAM_BOT_TOKEN` 환경변수를 쓰는 봇이 있다면 그대로 재사용됩니다.**
이 프로그램은 같은 변수를 읽으므로 추가 설정 없이 바로 동작합니다.

### 봇이 이미 있는 경우

전용 그룹 하나만 만들면 됩니다. 그래야 선물 신호가 다른 피드에 안 섞입니다.

1. 텔레그램에서 새 그룹 생성
2. 봇을 그룹에 초대
3. 그룹에서 `/start@봇이름` 전송
   (그룹 안의 봇은 privacy mode라 `/`로 시작하는 메시지만 봅니다)
4. `python scripts/setup_telegram.py` 실행 → chat_id 저장

개인 대화로 받으려면 봇에게 `/start`만 보내고 4번을 실행하면 됩니다.

### 봇이 없는 경우

1. 텔레그램에서 **@BotFather** → `/newbot` → 이름 정하면 **토큰**을 줍니다
2. 토큰을 환경변수에 넣습니다 (파일이 아니라 환경변수인 이유는 아래)

```powershell
# Windows PowerShell, 한 번만. 설정 후 새 터미널을 열어야 반영됩니다.
[Environment]::SetEnvironmentVariable("TELEGRAM_BOT_TOKEN", "<토큰>", "User")
```

```bash
# macOS / Linux — ~/.zshrc 또는 ~/.bashrc 에 추가
export TELEGRAM_BOT_TOKEN="<토큰>"
```

3. 위 "봇이 이미 있는 경우"의 1~4번을 따릅니다

### 확인

```bash
python run.py telegram-test
```

토큰·chat_id 를 **어디서 읽었는지**까지 보여줍니다(값은 안 찍습니다).

```
설정 출처
  봇 토큰  환경변수 TELEGRAM_BOT_TOKEN  (46자, 123456789:...)
  chat_id  환경변수 TELEGRAM_CHAT_ID_FUTURES  (-5305089060)

봇 확인: @my_bot
발송 성공
```

"분명히 설정했는데 안 된다"의 원인은 거의 항상 **터미널을 새로 열지
않아서**입니다. 환경변수는 프로세스가 시작될 때 복사되므로, 설정한 뒤
열려 있던 창에서는 계속 안 보입니다. 작업 스케줄러로 등록한 경우도
등록 이후에 변수를 바꿨다면 작업을 다시 시작해야 합니다.

### 왜 .env 가 아니라 환경변수인가

프로젝트 폴더가 깃이나 클라우드 드라이브로 동기화돼도 **토큰은 따라가지
않습니다.** `.env` 도 지원하지만(`.gitignore`에 있음), 폴더째 동기화되는
환경에서는 환경변수가 안전합니다.

이 프로그램이 chat_id 를 찾는 순서:

| 순서 | 출처 | 용도 |
|---|---|---|
| 1 | `TELEGRAM_CHAT_ID_FUTURES` | 선물 신호 전용 방 |
| 2 | `TELEGRAM_CHAT_ID` | 공용 기본 방 |
| 3 | `state/telegram_config.json` | 셋업 스크립트가 저장한 값 |

일반 그룹은 멤버를 추가하거나 설정을 바꾸는 것만으로 슈퍼그룹이 되고 그때
chat_id 가 바뀝니다. 텔레그램은 새 id 를 **에러에 딱 한 번** 실어 보내는데,
이 프로그램은 그걸 받아 자동으로 따라가고 `state/telegram_config.json` 에
저장합니다. 안 그러면 어느 날 발송이 조용히 끊깁니다.

## 사용법

```bash
# ★ 먼저: 계좌 규모로 뭐가 가능한지
python run.py plan --equity 200000

# 지금 포트폴리오 상태만 보기
python run.py strategy --portfolio --dry-run

# 배분 변경이 있으면 알림 발송
python run.py strategy

# 전략 + 베이즈 신호 한 번에
python run.py once --dry-run

# ★ 상시 감시 — PC에 띄워두는 모드
python run.py watch

# 보유 현황
python run.py positions

# 검증
python run.py backtest --reliability --tune
```

`watch` 가 하는 일:

- 매일 브리핑 시각에 **전략 배분을 점검**하고, 목표와 보유가 다르면 알립니다.
- 5분마다(설정 가능) 새로 마감된 봉을 확인합니다. 진행 중인 봉으로는
  신호를 내지 않습니다.
- 베이즈 신호가 켜져 있으면 진입/청산 알림도 함께 보냅니다.
- 장 마감 시간(주말, 매일 17:00~18:00 ET 정비)에는 조용히 대기합니다.
- 어느 종목에서 오류가 나도 나머지는 계속 돕니다. 오류 알림은 1시간에 한 번까지만.

## 부팅 시 자동 시작

PC가 하루에 몇 번 재시작돼도 알림이 끊기지 않게 하는 설정입니다.
발송 이력은 `state/alerts.json` 에 남으므로 **재시작해도 같은 신호를 두 번 보내지 않습니다.**

### Windows

`scripts\작업스케줄러_등록.bat` 을 **관리자 권한으로 한 번** 실행하면 끝입니다.

- 부팅 2분 뒤 자동 시작 (네트워크가 올라올 시간)
- 파이썬이 죽어도 10초 뒤 자동 재시작
- **사용자 계정으로 실행**되므로 `TELEGRAM_BOT_TOKEN` 사용자 환경변수를
  그대로 물려받습니다. SYSTEM 계정으로 돌리면 그 변수가 안 보여서
  발송이 조용히 실패합니다.

```
schtasks /run   /tn "해외선물_신호감시"          지금 바로 시작
schtasks /query /tn "해외선물_신호감시" /v /fo list   상태 확인
scripts\작업스케줄러_삭제.bat                    해제
```

수동으로 띄우려면 `scripts\start_windows.bat` 을 그냥 실행하면 됩니다.

### macOS / Linux

```bash
./scripts/start_unix.sh          # 죽으면 자동 재시작
```

Linux에서 부팅 시 자동 시작 (systemd):

```bash
# 파일 안의 CHANGE_ME 를 본인 사용자명/경로로 바꾼 뒤
sudo cp scripts/bayesfutures.service /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now bayesfutures
journalctl -u bayesfutures -f     # 로그 보기
```

## ② 베이지안 단기 확률 층 (참고용)

원래 요청이 베이지안 기법이었고, 그 층도 완성되어 있습니다.
다만 **검증 결과 방향 예측 엣지는 없었습니다.** 그 결과를 그대로 싣습니다.

| 종목 | 표본 | AUC | Brier (기준선) | 보정계수 a | 신호 | 누적 |
|---|---|---|---|---|---|---|
| 금 | 4,646 | 0.492 | 0.2507 (0.2489) | 0.043 | 87건 | +7.5R |
| 은 | 4,647 | 0.480 | 0.2515 (0.2492) | 0.049 | 250건 | −16.6R |
| 크루드오일 | 4,647 | 0.480 | 0.2506 (0.2498) | 0.026 | **0건** | 0 |
| 나스닥100 | 4,650 | 0.479 | 0.2491 (0.2478) | 0.028 | **0건** | 0 |

- **AUC 0.5 = 동전 던지기.** 네 종목 모두 0.48 근처입니다.
- **보정계수 a ≈ 0.03** 은 모델이 스스로 "내 증거는 확률을 움직일 자격이 없다"고
  판정한 값입니다. 사후확률을 기준확률 근처로 눌러버립니다.
- **금의 +7.5R도 유의하지 않습니다.** 87건에 적중률 55.2%인데 기준확률이 53.3%,
  표본 87건의 표준오차가 약 5.3%p입니다.
- **누수가 없다는 증거이기도 합니다.** 미래 정보가 샜다면 AUC 0.7 이상이 나옵니다.

### 그래도 만들어둔 이유

1. **확률이 정직합니다.** "63%"라고 하면 실제로 그 근처에서 맞습니다(신뢰도 곡선 검증).
2. **새 아이디어를 검증하는 틀입니다.** 피처를 추가하고 `backtest` 를 돌리면
   진짜 도움이 되는지 바로 나옵니다. 아래 두 함정을 잡아준 게 이 틀입니다.

### 개발 중 밟은 두 함정

비대칭 배리어(목표 2ATR/손절 1ATR)에서 평균 **+0.8R**이 나온 적이 있습니다.
둘 다 버그였습니다.

1. **매도의 손익비를 뒤집지 않았습니다.** 매도는 하단이 목표(1ATR),
   상단이 손절(2ATR)이라 손익비가 1:0.5로 역전됩니다. 고치니 **−0.1R**.
2. **절대 임계치가 드리프트에 먹혔습니다.** 비대칭 배리어에서 기준확률이
   0.40으로 내려가는데 매도 임계치가 0.42라, **모든 봉이 매도 신호**가 됐습니다
   (금 2,949건 전부 매도, 누적 −429R).

지금은 신호가 **기준확률 대비 초과분**을 요구합니다. 이 필터를 넣은 뒤
크루드오일·나스닥의 드리프트성 신호 수백 건이 0건으로 정리됐습니다.

### 어떻게 계산하는가

```
사후 로그오즈 = 사전 로그오즈 + Σ (신뢰도ᵢ × 로그우도비ᵢ)
```

- 피처를 학습구간 분위수로 5구간으로 나누고 구간별 우도비를 라플라스 평활로 추정
- 표본이 적은 구간은 경험적 베이즈로 축소 (`신뢰도 = n / (n + 40)`)
- **퍼지드 K-폴드 교차검증**으로 보정계수 `a` 학습 — 나이브 베이즈의
  조건부 독립 가정 위반에서 오는 과신을 되돌립니다. 폴드 경계에 라벨
  horizon 만큼 embargo를 둬 누수를 막습니다.
- 가우시안 HMM(Baum-Welch, numpy 직접 구현) 국면 사후확률을 소프트 증거로 결합.
  추론은 전향 필터링만 사용해 미래 정보가 새지 않습니다.

끄려면 `config.yaml` 에서 `alerts.signal_alerts: false`.

## 한계와 주의

- **전략은 롱 온리입니다.** 하락장에서는 현금(무포지션)으로 대기합니다.
  하락에서 수익을 내지 않습니다.
- **2006~2026년은 대체로 상승장이었습니다.** 이 구조는 상승 추세를 잡고
  폭락을 피하는 것이지, 장기 횡보장에서 수익을 보장하지 않습니다.
  표본외 구간(2018~2026)도 결국 같은 장세의 연장입니다.
- **롤오버 비용이 반영되지 않았습니다.** 검증은 연결 선물(GC=F 등) 종가
  기준입니다. 실제 성과는 이보다 낮습니다. 특히 크루드오일은 콘탱고 구간에서
  롤 비용이 큽니다.
- **시세는 야후 파이낸스 무료 데이터**입니다. 선물 시세가 **10~15분 지연**될 수
  있고, 야후가 막히면 stooq(일봉만)로 자동 전환합니다. 실시간 호가가 필요하면
  `bayesfutures/data.py` 의 `DataLoader` 만 교체하면 됩니다.
- **거래소 휴일을 반영하지 않습니다.** 다만 휴일엔 새 봉이 안 생겨 알림도 안 나갑니다.
- **주문 체결 여부는 알 수 없습니다.** 프로그램은 "알림대로 실행했다"고 가정하고
  보유 현황을 추적합니다. 실제와 어긋나면 `python run.py positions --clear` 로
  맞추세요.
- **샤프 0.99는 무위험 수익률을 빼지 않은 값입니다.** 금리를 반영하면 낮아집니다.
- **이건 투자 조언이 아닙니다.** 과거 검증이 미래를 보장하지 않습니다.
  실계좌 투입 전에 직접 코드를 읽고 검증하세요.
